# Executing Plans

> 参考文档，执行过程中批次间需要等待用户反馈。

## 核心流程

读取 index.json → 批量执行任务（默认前3个）→ 报告并等待反馈 → 继续下一批 → 完成开发

## 执行步骤

### Step 1: 加载并审查任务

1. **读取 `docs/plans/{folder}/index.json`** 获取任务列表
2. **读取第一批 task-*.json** 了解任务详情
3. **批判性审查** - 识别问题或疑虑
4. **如有疑虑** → 向用户提出，解决后再继续
5. **无疑虑** → 创建 TodoWrite 并开始执行

### Step 2: 批量执行

**默认：每批 3 个任务**

每个任务：
1. 标记为 `in_progress`
2. **读取 task-{id}.json** 获取完整任务详情
3. **严格按步骤执行**（task 中已定义具体步骤）
4. **运行验证**（按 task 中的 verification）
5. **更新 index.json** 标记为 `completed`
6. **更新 task-{id}.json** 的 files 字段（报告实际修改的文件）

### Step 3: 报告并等待

批次完成后报告：
- 已实现的内容
- 验证输出
- **说："Ready for feedback."**

等待用户反馈后再继续。

### Step 4: 继续或调整

根据反馈：
- 应用必要的更改
- 执行下一批
- 重复直到完成

### Step 5: 完成开发

所有任务完成并通过验证后，按照 `finishing-branch.md` 执行完成流程。

## 与 subagent-workflow 的区别

| | executing-plans | subagent-workflow |
|--|----------------|-------------------|
| 执行者 | 当前会话直接执行 | 派发 subagent 执行 |
| 审查方式 | 批次间暂停，等待用户反馈 | 自动两阶段审查（规格+质量） |
| 适用场景 | 用户希望参与审查过程 | 全自动执行 |

## 何时停止并求助

**立即停止执行的情况：**
- 执行中遇到阻碍（缺少依赖、测试失败、指令不清）
- 任务有重大缺陷无法开始
- 不理解某个指令
- 验证反复失败

**Ask for clarification rather than guessing.**

## 关键原则

1. **先批判性审查任务** - 不盲目执行
2. **严格按 task 步骤执行** - 不跳过步骤
3. **不跳过验证** - 按 task 运行验证命令
4. **遇到阻碍停止** - 不猜测，不强行推进
5. **批次间等待反馈** - 报告后等待，不自动继续
6. **同步更新 index.json** - 每个任务状态变更必须同步
7. **更新 task.json 的 files 字段** - 报告实际修改的文件

## 唯一出口

<HARD-GATE>
所有任务完成后，**必须按照 `finishing-branch.md` 执行完成流程**。
</HARD-GATE>

## Red Flags

**严禁：**
- 跳过 extract-tasks（直接读取 plan.md）
- 忘记更新 index.json 状态
- 跳过验证步骤
- 遇到阻碍时猜测继续
- 批次间不报告自动继续
