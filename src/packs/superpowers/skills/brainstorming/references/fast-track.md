# Fast-Track（快速模式）

> 参考文档，面向小型改动。跳过计划/任务文档，直接用 TodoWrite 驱动子代理编排实施与审查。

## 前置条件

- 已完成 brainstorming，设计已获批准
- 用户明确选择 `快速模式`

## 核心流程

创建 TodoWrite → 循环执行（实现 → 并行派发规格/质量审查 + 规格门禁）→ 完成开发

## 准备阶段

1. 基于已确认范围创建 3-6 条 TodoWrite

## 任务执行循环

```
TodoWrite 标记 in_progress
    ↓
派发实现者 subagent（传递当前 todo 内容与上下文）
    ↓
实现/测试/提交
    ↓
并行派发：@oracle 规格审查 + @oracle 质量审查（质量结果先暂存）
    ↓
等待规格审查结果（优先门禁）
    ↓
规格不通过 → 立即结束本轮，修复后再次并行审查
    ↓
规格通过 → 采纳质量审查结果
    ↓
质量不通过 → 修复后再次审查；通过 → TodoWrite 标记 completed
    ↓
下一任务
```

## 并行审查门禁规则

1. 规格审查是**硬门禁**；质量审查不是门禁入口。
2. 质量审查可与规格审查并行启动，派发 `@oracle` 执行，但结果在规格通过前仅为 **provisional（暂存）**。
3. 规格审查派发 `@oracle` 执行—失败 → 主 Agent **立即短路**并进入修复，不等待质量审查返回。
4. 修复后必须重新并行派发两类审查，旧的 provisional 质量结果作废。

## 主 Agent 约束

### 允许
- 创建/更新 TodoWrite
- 派发 todo 内容给实现者 subagent
- 派发 `@oracle` 进行规格审查，派发 `@oracle` 进行质量审查

### 禁止
- 直接修改代码文件
- 并行派发多个实现者（会冲突）
- 跳过审查或审查循环
- 用自审查替代正式审查

## 实现者 Subagent 约束

收到 todo 内容后：
1. 按需读取相关代码文件
2. 实现变更、运行测试、提交
3. 报告修改文件与验证结果

## 何时自动回退到标准模式

出现以下任一情况，立即暂停并回退 `writing-plans`：
- 需求存在关键歧义，需重新拆解
- 变更范围扩大到多模块高耦合
- 涉及高风险领域（安全/权限/迁移/支付/架构重构）
- 验证多次失败且需要结构性调整

回退提示：

> 检测到当前变更已超出快速模式边界，建议切换到标准模式。现在切换继续执行。

## 唯一出口

<HARD-GATE>
所有 todo 完成并通过验证后，必须按照 `finishing-branch.md` 执行完成流程。
</HARD-GATE>

## Red Flags

**严禁：**
- 写入 plan.md / index.json / task-*.json
- 跳过规格或质量审查
- 规格失败后仍等待质量审查再修复
- 并行派发多个实现者 subagent
- 用自审查替代正式审查
