## 前置条件

- 有需求来源：需求设计文档（`docs/{project-name}/requirement/`）或用户的想法描述

## 核心流程

探索项目上下文 → 提出澄清问题 → 提出2-3种方案 → 呈现设计章节 → 用户批准 → 模式选择（standard / fast_track）→ 执行对应后续流程

## 关键原则

1. 一次只问一个问题 - 避免一次性抛出多个问题让用户感到压力
2. 优先使用选择题 - 当可能时，提供选项比开放式问题更容易回答
3. YAGNI（你不会需要它） - 严格剔除设计中不必要的功能
4. 探索替代方案 - 在确定方案前，总是提出2-3种不同的方法
5. 增量验证 - 先呈现设计，获得批准后再继续
6. 保持灵活 - 当某些地方不合理时，愿意回头澄清

## 子 Agent 并行处理

当需要调查代码、搜索参考资料等操作时，可以派发多个子 agent 并行处理，主 agent 不要自己做大量搜索工作。

## 模式选择门（mode_gate）

在用户批准设计后，选择执行模式：

1. **标准模式**：生成计划/任务文件，再实施（更稳）
2. **快速模式**：不写计划文件，直接用 TodoWrite 编排子代理实施并审查（更快，适合小改动）

> 选择：`标准模式` 或 `快速模式`（默认：标准模式）

### 分流规则

- 用户选择 `标准模式`（或未明确）→ 执行 `writing-plans` 流程
- 用户选择 `快速模式` → 执行 `fast-track` 流程

## 设计交付物

- 设计确认后，进入模式选择
- 代码修改的声明协议（APPROVED/AWAITING_APPROVAL）由内置门禁自动处理，无需在对话中手动维护

## 唯一出口

模式选择确认后进入对应的执行流程。

**禁止：**
- 跳过用户批准直接实现
- 在功能需求中写实现细节（代码、API、数据结构）
